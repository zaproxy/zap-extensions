Local LLM Support

This optional add-on adds a Local (Jlama) provider to the LLM Support add-on. It runs an open-source LLM in-process inside ZAP, using Jlama, so no separate Ollama or API server is required.

Requirements

  • The LLM Support add-on must also be installed.
  • ZAP must be running on Java 21 or later.
  • The Java Vector API and Jlama native SIMD must be enabled. Add these JVM options and restart ZAP: 
    --add-modules jdk.incubator.vector --enable-preview
    --enable-preview is required on Java 21 so the bundled jlama-native library can load. Without it, Jlama falls back to Panama vector ops and many Q4 models fail on Apple Silicon with UnsupportedOperationException: ARM_128. For packaged ZAP, set the options under Options → JVM (stored in .ZAP_JVM.properties). For IDE / ZAP_D launches, add the same options to the run configuration VM arguments. You can also set JDK_JAVA_OPTIONS='--add-modules jdk.incubator.vector --enable-preview' before starting ZAP. On newer JDKs you may also need --enable-native-access=ALL-UNNAMED.
  • Sufficient RAM for the chosen model (quantized models are strongly recommended).

Local model directory

Configure the provider with the path to a local SafeTensors model directory. A valid directory typically contains at least:

  • config.json
  • tokenizer files (for example tokenizer.json)
  • one or more *.safetensors weight files

Pre-quantized models suitable for Jlama are published under huggingface.co/tjake. Download a model locally, then point ZAP at that folder.

Single-file GGUF models are not supported by this add-on.

Configuration

  1. Install LLM Support and Local LLM Support.
  2. Open Options → LLM and add a provider of type Local (Jlama).
  3. Use Browse... or Download... to add one or more local models (HuggingFace downloads land under <ZAP home>/llm-models; the tjake catalog is offered in the download dialog).
  4. Select that provider/model from the LLM toolbar or chat panel, as with any other provider.

Command Line

You can download a HuggingFace model and configure it as the default local LLM provider in one step: 

zap.sh -llmlocal tjake/Llama-3.2-1B-Instruct-Jlama-Q4

The model is stored under <ZAP home>/llm-models. Re-running the option with the same model reuses the cached files and refreshes the LLM provider configuration.

-jlama is accepted as a deprecated alias for -llmlocal.

MCP / tools

ZAP can pass MCP tools (spider, active scan, and so on) to the local model when the provider is marked Trusted and the chat tools toggle is enabled. Whether the model actually sees those tools depends on its HuggingFace chat template:

  • Tool-capable Instruct models (recommended): for example tjake/Llama-3.2-1B-Instruct-Jlama-Q4, tjake/Llama-3.2-3B-Instruct-JQ4, or tjake/granite-3.0-2b-instruct-JQ4. These templates include a tools section, so Jlama can inject tool definitions into the prompt.
  • Chat-only models such as TinyLlama: their templates have no tools section. MCP tools are never included in the prompt, so the model cannot call them.

Even with a tool-capable template, very small models (around 1B parameters) may still ignore tools when many MCP tools are present. Prefer a 2B–3B Instruct model when testing tool calling.

Compared with Ollama

Ollama also runs models locally, but as a separate HTTP service. This add-on loads the model inside the ZAP JVM process via Jlama. That is convenient for air-gapped use, but it increases ZAP's memory usage and requires a newer JDK with Vector API flags.
