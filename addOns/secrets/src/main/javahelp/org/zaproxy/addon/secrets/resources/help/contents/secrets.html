Secrets

This add-on detects secrets (such as API keys and tokens) disclosed in HTTP responses.

Secrets Disclosure

Detects secrets (API keys, tokens, private keys, etc.) disclosed in responses (images, fonts, and binary content, which is content with more than 1% control characters such as NUL, are ignored), using the patterns of the default Gitleaks configuration (gitleaks.toml).

Each Gitleaks rule raises at most one alert per message, so several secrets of the same type in one response are reported once.

The Gitleaks rule ID that matched is in the Other Info of the alert.

The evidence of the alerts is the text matched by the pattern, which includes the secret, so the alerts and the reports generated from them are sensitive.

The Gitleaks keywords, entropy, stopwords, and allowlists are honoured. The allowlist paths (for example vendored libraries) are matched against the request path, and are only applied at High threshold. The allowlists that check the whole line, or that need all of their criteria to match, are not used, so there can be more false positives from the generic rule.

The rules which Gitleaks limits to certain files (for example Terraform files) are only used for the requests with a matching path.

The generic API key rule (generic-api-key) is only used at Low threshold, as it is slow on large responses and prone to false positives. Its alert is not raised if another rule found the same secret.

Some patterns which appear associated with keys that are public by design (for example, keys meant to be used in client side code) raise alerts with a lower Risk and Confidence.
