Active Scan Rules - Alpha

The following alpha status active scan rules are included in this add-on:

LDAP Injection

LDAP Injection may be possible. It may be possible for an attacker to bypass authentication controls, and to view and modify arbitrary data in the LDAP directory. Skips messages which originally resulted in a client or server error response status code.

Latest code: LdapInjectionScanRule.java
Alert ID: 40015.

SQL Injection - SQLite (Time Based)

This active scan rule attempts to inject SQLite specific commands into parameter values and analyzes the timing of server responses to see if the commands were effectively executed on the server (indicating a successful SQL injection attack).

Latest code: SqlInjectionSqLiteTimingScanRule.java
Alert ID: 40024.

Web Cache Deception

This rule attempts to identify Web Cache Deception vulnerabilities. It checks whether a static path appended to original URIs can be used to leak sensitive user information or not.
  • User must be authenticated before using this rule
Latest code: WebCacheDeceptionScanRule.java
Alert ID: 40039.

Payment Amount Manipulation

Checks whether an API accepts a monetary amount that has been altered to an invalid value, such as a negative or zero amount, instead of rejecting it.

Only POST, PUT, PATCH and DELETE requests which originally resulted in a successful response are tested. A parameter is tested only if its name contains a money related word (for example amount, price, total, fee, refund), at a word boundary such as _, - or camelCase, and its original value is a decimal number. The list of words can be replaced by setting the rule configuration rules.common.paymentamount.moneywords to a comma separated list of words.

An alert is raised in either of these cases:

  • An altered amount receives a successful response that contains that amount, and the original response did not. The confidence is medium if the altered amount is negative or zero, otherwise low.
  • An altered amount receives a successful response similar to the original, while a control request with a non-numeric value does not. The confidence is low.
A response is not treated as accepting the amount if its body is a JSON object that declares a failure at the top level (a non-empty error, errors or errorMessage, a false success or ok, or a failure status such as rejected); other body formats are not inspected.

The number of payloads sent per parameter depends on the Attack Strength.

Note that the altered amounts are really submitted to the target, so this rule may create or alter records on a vulnerable application.

Latest code: PaymentAmountManipulationScanRule.java
Alert ID: 40049.

Suspicious Input Transformation

This is an active script scan rule. It detects various types of suspicious input transformations that may indicate potential security vulnerabilities such as template injection, expression evaluation, quote consumption, and issues related to unicode normalization.

This rule is largely adapted from the "Suspect Transform" check included in the ActiveScan++ extension for Burp Suite by Albinowax: SuspectTransform.java.

Latest code: SuspiciousInputTransformation.js
Alert ID: 100044.
