LLM Automation Framework Support

The LLM add-on adds support for the Automation Framework, if the automation add-on is installed.

Job: llm-config

The llm-config job configures the LLM providers, the same ones you can configure in the Options. 
  - type: llm-config                   # Configure the LLM providers
    parameters:
      deleteExisting: false            # Bool: Remove all existing providers first, default: false
      defaultProvider:                 # String: Name of the default provider, default: the current default, or the first provider
      defaultModel:                    # String: The default model, must be one of the default provider's models, default: the current default if valid, or the first model
    providers:                         # List: Each provider is added, or updates the existing one with the same name
      - name:                          # String: Unique provider name
        type:                          # String: OLLAMA, OPENAI_COMPATIBLE, AZURE_OPENAI, GOOGLE_GEMINI or CLAUDE
        apiKey:                        # String: The API key, use an environment variable, e.g. ${LLM_API_KEY}
        endpoint:                      # String: The endpoint URL, required for OLLAMA, OPENAI_COMPATIBLE and AZURE_OPENAI
        models:                        # List: The model names, at least one is required
          -
        trusted:                       # Bool: Whether the provider is trusted, default: true for OLLAMA, otherwise false
        timeout:                       # Int: Request timeout in seconds, default: 60

By default the providers in the job are merged with the existing ones: a provider with the name of an existing one updates it, and only the fields specified are changed. Any other existing providers are left as they are. Set deleteExisting to true to remove all existing providers first.

In the Automation Framework GUI the job dialog has a Parameters tab and a Providers tab. The Providers tab lists the providers in the job, which can be added, modified (also by double clicking) and removed. Fields left empty are not included in the plan, so they keep the value of an existing provider, or the default. A timeout of 0 means the default is used.

The job fails verification if a provider has no name or a duplicate name, has no valid type, has no endpoint when one is required, has no models, or if the default provider or model is not one of those configured.

API keys can be given directly, but it is recommended to use environment variables so that they are not saved in the plan.

The job is run before any other jobs that need an LLM.
