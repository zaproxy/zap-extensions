クライアントサイド統合 - クライアントスパイダーオプション

クライアントスパイダーオプションパネル (オプション → クライアント統合 → クライアントスパイダー からアクセス可能) では、クライアントスパイダーで使用されるデフォルト設定を構成できます。

これらのデフォルト設定は、新しいスパイダースキャンを開始する際に使用され、クライアントスパイダー ダイアログにもあらかじめ入力されています。

オプション

  • ブラウザー - スパイダーが対象アプリケーションをクロールするために使用するブラウザー
  • 同時起動するブラウザーウィンドウ - スパイダーが並行して使用するブラウザウィンドウの数。 ウィンドウの数を増やすと動作は速くなりますが、メモリの使用量も増えます
  • クロールする最大階層 - スパイダーがクロールする最大階層。0は無制限を意味します
  • 最大子要素数 - ツリー内の任意の単一ノードの下に追加できる子ノードの最大数。 0は「無制限」を意味します
  • 初期ページ読み込み時間 - 最初のURLが読み込まれてから待機する秒数。 デフォルト値: 0
  • ページ読み込み時間 - 連続する各URLの読み込み後に待機する秒数。 デフォルト値: 0
  • アクション待機時間 - ブラウザ上でアクション (URLの開く、ボタンのクリック、フォームの送信など) を実行した後、待機する秒数。 デフォルト値: 0
  • シャットダウン時間 - 最後のアクション後、スパイダーがシャットダウンするまでに新しいイベントを待機する秒数。 デフォルト値: 5
  • 最大継続時間 - スパイダーの実行が許可される最大時間 (分)。 0は「無制限」を意味します
  • スコープチェック - スパイダーがスコープ外のリソースに対するリクエストをどのように処理するかを制御します:
    • 柔軟 - スコープ外のリソース (サードパーティのスクリプトやスタイルシートなど) がプロキシを通過してブラウザがそれらを読み込めるようにしますが、それらをクロールすることはありません。 これがデフォルトの設定です
    • 厳格 - プロキシですべてのスコープ外のリソースをブロックします。 ブラウザはスコープ内にあるリソースのみを読み込むことができます
  • ログアウト回避 - 有効にすると、スパイダーはユーザーをログアウトさせる可能性のある要素をクリックしないようにします

ページ読み込み時間とアクション待機時間の両方が0に設定されている場合、スパイダーは固定の遅延ではなく、適応型の待機戦略を使用します。 この適応型戦略は、対象範囲内のネットワークトラフィックを監視し、リクエストが落ち着くまで待機します。ただし、最大15秒というハードリミットが設定されています。 URL に初めてアクセスした際には、より長いクワイエス閾値 (2.5秒) を適用し、それ以降のアクセスではより短い閾値を適用します。
