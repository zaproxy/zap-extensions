Automation Framework - GUI

The Automation Framework has a GUI that is in the process of being developed.

Automation Tab

This tab allows you to create, load, edit and run automation jobs.

A toolbar provides the following buttons:

  • New Plan... - this launches the New Plan dialog
  • Load Plan... - this allows you to load a plan from a yaml file
  • Load Plan from Clipboard - this allows you to load a plan from the contents of the clipboard
  • Save Plan - this saves the current plan to a yaml file
  • Run Plan - this runs the current plan
  • Stop Plan - this stops the current plan
  • Add Job... - this launches the Add Job dialog to add a job to the current plan
  • Remove Job... - this removes the selected job from the current plan
  • Move Job Up - this moves the selected job up one place in the current plan
  • Move Job Down - this moves the selected job down one place in the current plan
  • Add Test... - this launches the Add Test dialog to add a test to the current job
  • Remove Test... - this removes the selected test from the current job
The name of the file of the current plan, if it has one, is shown after the buttons, hover over it to see the full path.

Below the toolbar, you can find a graphical representation of the plan which also shows the state of the plan when it is run.
You can edit any of the elements of the plan by double clicking on them.

You can also change the following general job options via the plan table:

  • Enabled - only jobs that are enabled will run.
  • Always Run - enabled jobs with this option will run even if the plan exits early.

Batch Tab

The Automation tab has two sub-tabs, Plan, described above, and Batch. The Batch tab runs all, or just one, of the plans in a directory, for example the integration tests of an add-on.

Enter or browse for a directory and its .yaml files are listed, in alphabetical order. The files are not checked until they are run, files with any other extension (for example .yaml.disabled) are not listed. The directory is remembered.

The toolbar provides the following buttons:

  • Run All - this runs all of the plans listed, one after the other
  • Run Selected - this runs just the plans selected
  • Stop - this stops the plan being run and the rest of the batch
Each plan is loaded into the Plan tab when it is run, so you can see its progress there, replacing the plan that was shown. You are asked first if that plan has unsaved changes. While the batch is running the Run button of the Plan tab is disabled, and its Stop button stops the plan being run and the rest of the batch, the same as the Stop button of the Batch tab. The Batch tab only shows the status of each plan and a summary.

The batch stops at the first plan that fails. A plan fails if it cannot be loaded or if it finishes with errors, which is the same as when run with the -autorun command line option, so warnings do not make a plan fail. Tests that should fail the plan need onFail: 'error'. The failed plan is selected, hover over its status to see the errors, which are also in the Output tab.

The plans are run in the same session, one after the other. Any contexts with the same name are replaced, but any options set by one plan, using the configs environment parameter, remain set for the next.

Output

Any output generated while loading or running the plan will appear in the Automation sub-tab of the Output tab.
